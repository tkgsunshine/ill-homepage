ソースコードの譲渡と著作権の帰属｜譲渡費用の考え方と、契約で決める5つのポイント

公開日: 2026.10.20
著者: Ill inc. 編集部

この記事の結論

外注したシステムの著作権は、契約で決めていなければ、原則として作った開発会社に残ります。ソースコードの譲渡に決まった相場はなく、契約の前に決めれば開発費に含めて交渉しやすい一方、納品のあとで求めると、別の料金や条件を出されることがあります。発注前に「著作権の譲渡（著作権法第27条・第28条の権利を含む）」「ソースコード一式の納品」「開発会社の共通部品の扱い」を契約書で確認しましょう。

1. お金を払っても、ソースコードの権利は自動では移らない

システムやアプリを外注して、開発費を全額払った。それでも、作ったプログラムの著作権は、契約で決めていなければ、原則として作った開発会社に残ります。

ソースコードとは、プログラムの設計図にあたる文字の集まりです。これが手元になかったり、権利が開発会社にあったりすると、次のような困りごとが起きます。

  • 保守の料金が上がっても、ほかの会社に乗り換えにくい
  • 機能を足したいのに、自社や別の会社では直せない
  • 事業を売る・出資を受けるときに、システムの権利を説明できない

中小企業で業務システムを外注する方にも、アプリで起業する個人の方にも、早めに知っておいてほしい点です。

2. ソースコードの譲渡費用は、どう決まるのか

「ソースコード 譲渡 費用」の答えを先に言うと、決まった相場はありません。金額は、いつ、どこまで譲るかで変わります。

タイミング・形よくある内容費用の考え方
契約の前に決める開発費の中に、著作権の譲渡とソースコードの納品を含める見積もりの段階なので、交渉しやすい
納品のあとで求める譲渡のために、追加の契約を結ぶ別の料金や条件を出されることがある
譲渡せず、利用を許可してもらう権利は開発会社に残り、発注者は使うことを許される譲渡より負担が軽い場合もあるが、改修や他社への依頼に制限が出やすい

金額に影響しやすいのは、次の点です。

  • 開発会社の共通部品が入っているか：ほかの案件でも使う部品は、譲渡の対象から外されることが多い
  • 開発会社が、同じ仕組みを再び使う予定があるか：再利用できなくなる分を、料金に乗せることがある
  • 何を渡すか：ソースコードだけか、設計書や動かすための手順書まで含めるか

いちばん負担が小さいのは、発注の前に、見積もりと契約書の中で決めてしまうことです。

3. 「譲渡」「利用許諾」「共有」の違い

形中身気をつけること
発注者に譲渡権利が発注者に移る開発会社の共通部品は対象外にすることが多く、範囲の確認が必要
開発会社に残し、利用を許諾発注者は決められた範囲で使える改修や、ほかの会社への依頼が許される範囲に入っているか
共有双方が権利を持つ権利を使うたびに相手の同意が要る場合があり、実務では複雑になりやすい

自社の事業の中心になるシステムなら、譲渡か、改修や他社への依頼まで自由にできる許諾にしておくのが安心です。

4. 契約書で決める5つのポイント

  1. 著作権の帰属：発注者へ譲渡するのか、開発会社に残すのか
  2. 第27条・第28条の権利：譲渡する場合は「著作権法第27条および第28条の権利を含む」と書く。書いていないと、改変などの権利は譲渡されなかったと推定される規定がある
  3. 納品物の範囲：ソースコード一式、設計書、動かすための手順書が含まれるか
  4. 共通部品とオープンソースの扱い：譲渡の対象外になる部分と、その使い方の条件
  5. 保守の引き継ぎ：契約が終わったあと、ほかの会社に保守を頼めるか。開発会社が著作者としての権利（著作者人格権）を使わない、という約束も合わせて確認する

※本記事は一般的な説明で、法律の助言ではありません。具体的な契約は、必要に応じて弁護士などの専門家に確認してください。

5. 納品済みで、ソースコードが手元にないとき

すでに開発が終わっていても、あきらめる必要はありません。次の順で進めます。

  1. 契約書と注文書を読み、著作権と納品物について何が書いてあるかを確かめる
  2. 実際に受け取ったもの（ソースコード、設計書、管理画面の権限）を一覧にする
  3. 開発会社に、譲渡や納品の条件を書面で相談する
  4. 条件が合えば、追加の契約として残す
  5. 話がまとまらないときは、専門家に相談する

あわせて、サーバーやドメインの管理者の権限が、自社の名義になっているかも確認しましょう。権利があっても、動かす場所の鍵がなければ引き継げません。引き継ぎの資料については、作ったシステムの説明書と引き継ぎ資料を、納品時に必ずそろえるも参考になります。

6. 個人起業家と中小企業、それぞれの注意点

  • 個人起業家の方：アプリが事業そのものになる場合、権利が自分にないと、出資や事業の売却のときに問題になることがあります。最初の小さな版（MVP）でも、譲渡の条件は決めておきましょう。
  • 中小企業の担当者の方：業務システムは何年も使います。担当の開発会社が変わっても動かし続けられるよう、ソースコードと手順書の納品を、契約の条件に入れておきます。
  • どちらにも共通：契約の種類（請負・準委任）によって、納品の考え方が変わります。詳しくは請負契約と準委任契約の違いをご覧ください。

よくある質問

ソースコードの譲渡には、いくらかかりますか？

決まった相場はありません。発注の前に契約へ入れておけば、開発費の中で交渉できることが多く、納品のあとで求めると、別の料金や条件を出されることがあります。共通部品の扱いや、設計書まで渡すかどうかでも変わります。

著作権を譲り受ければ、自由に改修できますか？

契約書に「著作権法第27条および第28条の権利を含む」と書いていないと、改変などの権利は譲渡されなかったと推定される規定があります。改修を前提にするなら、この一文と、開発会社が著作者人格権を使わない約束を確認しましょう。

開発会社と連絡が取れなくなったら、どうなりますか？

ソースコードやサーバーの権限が手元になければ、直すことも引っ越すことも難しくなります。いちばんの備えは、開発中から、ソースコード一式と管理者の権限を自社でも持っておくことです。
